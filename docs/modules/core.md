# `src/core` — общая инфраструктура

Всё, что здесь лежит, не привязано к конкретной фиче бота (не к валютам, не к крафту). Это переиспользуемые "кирпичики", на которых строятся модули.

## `main.ts` (корень src, не core, но логично разобрать здесь)

Точка входа в приложение.

- **`bootstrap()`** — создаёт NestJS-приложение поверх Fastify (`FastifyAdapter`), включает корректное завершение по сигналам (`enableShutdownHooks`), запускает HTTP-сервер на порту из `PORT` (по умолчанию 3000), слушая на `0.0.0.0` (все сетевые интерфейсы — важно для контейнеров/облака).
- Если `bootstrap()` падает — ошибка печатается в консоль и процесс завершается с кодом 1.

## `app.module.ts`

Корневой модуль приложения (`AppModule`). Импортирует:

- `ConfigModule.forRoot({ isGlobal: true, validate: validateConfig })` — читает `.env`, делает `ConfigService` доступным во всём приложении без повторного импорта, и на старте запускает `validateConfig` (см. ниже).
- `BotModule` — всё, что касается бота.

Также напрямую регистрирует `HealthController`.

## `core/config.ts`

**Функция `validateConfig(config)`** — вызывается один раз при старте приложения. Проверяет, что в переменных окружения заданы `BOT_TOKEN` и `EXCHANGE_API_KEY`. Если нет — бросает `Error` и приложение вообще не стартует. Это защита от ситуации "бот запустился, а через 5 минут упал, потому что забыли токен".

## `core/domain/domain-exception.ts`

**Абстрактный класс `DomainException`** — базовый класс для всех "ожидаемых" бизнес-ошибок в проекте (в противовес непредвиденным багам/исключениям рантайма).

- У каждого наследника обязателен `readonly code: string` — короткий машинный код ошибки (например, `"EMPTY_MESSAGE_TEXT"`).
- В конструкторе `this.name = new.target.name` — трюк, чтобы `error.name` показывал реальное имя класса-наследника (например, `EmptyMessageTextException"`), а не просто `"Error"`.

Используется во всех модулях: `EmptyMessageTextException`, `InvalidCommandFormatException`, `ExchangeRateApiException` и т.д. — все они расширяют `DomainException`.

## `core/event-bus/` — шина событий

Классическая реализация паттерна Publish/Subscribe (публикация/подписка). **На момент написания документации нигде в проекте активно не используется** (ни один модуль её не импортирует) — похоже, задел на будущее (например, чтобы разные модули могли реагировать на события друг друга, не зная друг о друге напрямую).

- **`domain-event.ts`** — интерфейс `DomainEvent`: у любого события есть `name` (строка-тип события) и `occurredAt` (дата, когда произошло).
- **`event-bus.ts`** — интерфейс `EventBus` с двумя методами: `publish(event)` — опубликовать событие, `subscribe(eventName, handler)` — подписаться на события с определённым именем.
- **`in-memory-event-bus.ts`** — класс `InMemoryEventBus`, реализация `EventBus` "в памяти": хранит `Map<строка-имя события, Set<обработчики>>`. `publish` находит всех подписчиков на это имя события и вызывает их по очереди. Ничего не сохраняется на диск/в базу — при перезапуске приложения все подписки теряются (они пересоздаются при старте кода).

## `core/health/health.controller.ts`

**`HealthController`** — обычный NestJS HTTP-контроллер (не имеет отношения к Telegram). Даёт два эндпоинта:

- `GET /` → `{ status: "ok" }`
- `GET /health` → `{ status: "ok" }`

Нужен для мониторинга/оркестраторов (Docker, Kubernetes, хостинг), которые периодически проверяют "жив ли сервис".

## `core/user-mode/` — в каком режиме находится чат

Бот поддерживает несколько "режимов" работы (сейчас: главное меню, валюты, крафт). Этот под-модуль хранит и отдаёт текущий режим для каждого чата (`chatId`).

- **`bot-mode.ts`**
  - `BOT_MODES` — массив допустимых режимов: `["home", "currency", "craft"]`.
  - `BotMode` — тип-объединение, выведенный из `BOT_MODES` (то есть `"home" | "currency" | "craft"`).
  - `DEFAULT_BOT_MODE` — режим по умолчанию, `"home"` (используется, когда для чата ещё нет сохранённого режима — например, первое сообщение).

- **`user-mode.port.ts`** — порт (интерфейс) `UserModePort`:
  - `getMode(chatId): BotMode | undefined` — узнать текущий режим чата (или `undefined`, если ещё не выбирали).
  - `setMode(chatId, mode): void` — сохранить режим для чата.
  - `USER_MODE_PORT` — символ-токен для DI, через него все модули запрашивают эту зависимость.

- **`in-memory-user-mode.adapter.ts`** — класс `InMemoryUserModeAdapter`, реализация порта "в памяти": обычный `Map<chatId, BotMode>`. **Важно**: при перезапуске сервера все режимы сбрасываются — это не сохраняется в БД. Для реального продакшена сюда обычно подставляют адаптер поверх Redis/базы данных, но благодаря архитектуре "порт/адаптер" это можно сделать, не трогая остальной код.

- **`user-mode.module.ts`** — `UserModeModule`, NestJS-модуль, который регистрирует `InMemoryUserModeAdapter` под токеном `USER_MODE_PORT` и экспортирует этот токен, чтобы им могли пользоваться `BotModule`, `CurrencyModule`, `CraftModule`.
