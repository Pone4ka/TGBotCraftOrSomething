# `src/core` — общая инфраструктура

Всё, что здесь лежит, не привязано к конкретной фиче бота (не к валютам, не к студенту). Это переиспользуемые "кирпичики", на которых строятся модули.

## `main.ts` (корень src, не core, но логично разобрать здесь)

Точка входа и **composition root** приложения — единственное место, где все модули собираются вручную (без DI-контейнера).

`bootstrap()`:
1. `loadConfig()` — читает и валидирует `.env`.
2. `createSupabaseClient(config)` — готовит клиент Supabase (задел на будущее, пока никуда не передаётся дальше).
3. `new InMemoryUserModeAdapter()` — общий на все модули экземпляр, создаётся один раз.
4. `createHttpServer()` — поднимает Fastify, сразу регистрирует health-роуты.
5. `createCurrencyModule(...)`, `createStudentModule(...)` — собирают модули; `student` дополнительно регистрирует свой HTTP-роут на общий Fastify-инстанс.
6. `createBotModule(...)` — собирает бота, отдаёт `{ start(), stop() }`.
7. `await bot.start()` — регистрирует Telegram-обработчики и (если задан `WEBHOOK_URL`) монтирует вебхук-роут на Fastify **до** того, как сервер начнёт слушать порт.
8. `await httpServer.listen(...)` — сервер начинает слушать `0.0.0.0:PORT` (важно для контейнеров/облака).
9. Подписка на `SIGINT`/`SIGTERM` — корректно останавливает polling (`bot.stop()`) и Fastify (`httpServer.close()`) перед выходом.

Если `bootstrap()` падает — ошибка печатается в консоль и процесс завершается с кодом 1.

## `core/config.ts`

**Функция `loadConfig(): Config`** — вызывается один раз при старте приложения. Читает `process.env` и возвращает типизированный объект. Если обязательная переменная не задана — бросает `Error`, и приложение вообще не стартует. Это защита от ситуации "бот запустился, а через 5 минут упал, потому что забыли токен".

Обязательные: `BOT_TOKEN`, `EXCHANGE_API_KEY`, `SUPABASE_URL`, `SUPABASE_KEY`. `WEBHOOK_SECRET` обязателен только если задан `WEBHOOK_URL` (проверяется здесь же, при старте, а не в момент настройки вебхука).

## `core/domain/domain-exception.ts`

**Абстрактный класс `DomainException`** — базовый класс для всех "ожидаемых" бизнес-ошибок в проекте (в противовес непредвиденным багам/исключениям рантайма).

- У каждого наследника обязателен `readonly code: string` — короткий машинный код ошибки (например, `"EMPTY_MESSAGE_TEXT"`).
- В конструкторе `this.name = new.target.name` — трюк, чтобы `error.name` показывал реальное имя класса-наследника (например, `"EmptyMessageTextException"`), а не просто `"Error"`.

Используется во всех модулях: `EmptyMessageTextException`, `InvalidCommandFormatException`, `ExchangeRateApiException` и т.д. — все они расширяют `DomainException`.

## `core/event-bus/` — шина событий

Классическая реализация паттерна Publish/Subscribe (публикация/подписка). **На момент написания документации нигде в проекте активно не используется** (ни один модуль её не импортирует) — похоже, задел на будущее (например, чтобы разные модули могли реагировать на события друг друга, не зная друг о друге напрямую).

- **`domain-event.ts`** — интерфейс `DomainEvent`: у любого события есть `name` (строка-тип события) и `occurredAt` (дата, когда произошло).
- **`event-bus.ts`** — интерфейс `EventBus` с двумя методами: `publish(event)` — опубликовать событие, `subscribe(eventName, handler)` — подписаться на события с определённым именем.
- **`in-memory-event-bus.ts`** — класс `InMemoryEventBus`, реализация `EventBus` "в памяти": хранит `Map<строка-имя события, Set<обработчики>>`. `publish` находит всех подписчиков на это имя события и вызывает их по очереди. Ничего не сохраняется на диск/в базу — при перезапуске приложения все подписки теряются (они пересоздаются при старте кода).

## `core/http/http-server.ts`

**Функция `createHttpServer(): FastifyInstance`** — создаёт обычный (без какого-либо фреймворка-обёртки) экземпляр Fastify и сразу регистрирует на нём health-роуты. Другие модули (`student`, `bot`) дозаписывают свои роуты на этот же инстанс уже в `main.ts`, до вызова `.listen()`.

## `core/health/health.controller.ts`

**`registerHealthRoutes(app)`** — обычная функция, регистрирующая два HTTP-роута прямо на Fastify-инстансе (никакого HTTP-фреймворка сверху не нужно):

- `GET /` → `{ status: "ok" }`
- `GET /health` → `{ status: "ok" }`

Нужен для мониторинга/оркестраторов (Docker, Kubernetes, хостинг), которые периодически проверяют "жив ли сервис".

## `core/supabase/supabase-client.factory.ts`

**Функция `createSupabaseClient(config): SupabaseClient`** — создаёт клиент `@supabase/supabase-js` из `SUPABASE_URL`/`SUPABASE_KEY`. Сейчас вызывается в `main.ts`, но результат никуда не передаётся дальше — это подготовка инфраструктуры для последующей интеграции (хранение состояния бота, аутентификация и т.д.), а не рабочая функциональность.

## `core/user-mode/` — в каком режиме находится чат

Бот поддерживает несколько "режимов" работы (сейчас: главное меню, валюты). Этот под-модуль хранит и отдаёт текущий режим для каждого чата (`chatId`).

- **`bot-mode.ts`**
  - `BOT_MODES` — массив допустимых режимов: `["home", "currency"]`.
  - `BotMode` — тип-объединение, выведенный из `BOT_MODES` (то есть `"home" | "currency"`).
  - `DEFAULT_BOT_MODE` — режим по умолчанию, `"home"` (используется, когда для чата ещё нет сохранённого режима — например, первое сообщение).

- **`user-mode.port.ts`** — интерфейс `UserModePort`:
  - `getMode(chatId): BotMode | undefined` — узнать текущий режим чата (или `undefined`, если ещё не выбирали).
  - `setMode(chatId, mode): void` — сохранить режим для чата.

- **`in-memory-user-mode.adapter.ts`** — класс `InMemoryUserModeAdapter`, реализация порта "в памяти": обычный `Map<chatId, BotMode>`. **Важно**: при перезапуске сервера все режимы сбрасываются — это не сохраняется в БД. Для реального продакшена сюда обычно подставляют адаптер поверх Redis/базы данных (или Supabase), но благодаря архитектуре "порт/адаптер" это можно сделать, не трогая остальной код.

Экземпляр `InMemoryUserModeAdapter` создаётся один раз в `main.ts` и передаётся как общая зависимость в `createCurrencyModule` и `createBotModule` — это гарантирует, что все модули видят один и тот же режим чата.
